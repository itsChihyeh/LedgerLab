## What I did (AC-10.10)
- **Adapter:** `deepseek_model.py` uses stdlib `urllib` and adds no dependency. It is the only file that POSTs, and its base URL `https://api.deepseek.com` is a hard-coded constant.
  - Request side: it always sends `tool_choice: auto`, and sends back every earlier `reasoning_content`.
  - Response side: unparsable tool arguments become an invalid tool call that the Agent loop reports back to the model, so it doesn't crash.
  - Retries: 429, 5xx and network errors are retried up to 2 times with backoff, and 4xx errors are not retried.
  - Key: it comes only from `DEEPSEEK_API_KEY` and is scrubbed from errors and `repr`.
- **Model layer:** added `ReasoningBlock`, `ToolUseBlock.invalid_reason`, the cache and reasoning usage fields, and `ModelError`. The Agent loop now ends a question as `invalid_output` on `length`, `content_filter`, `insufficient_system_resource` or `aborted`, with no automatic retry.
- **Spend protection:**
  - `agent/pricing.json` ships with every field `null`, so any `deepseek:` run is refused until the prices are filled in.
  - The checks run in a fixed order: prices, printed estimate, `--confirm-spend`, key. `eval` also requires `--out`.
  - The cost is tracked per request and stops the run once it passes the cap. The question in progress is dropped but its cost is counted. The result file is marked incomplete (达到费用上限) and the command exits 3.
  - `eval` accepts `--split`, `--limit`, `--reasoning-effort` and `--max-tokens`, and `investigate` is guarded the same way.
- **Report:** `eval-report --external <files>` adds an external column and fills section 7 with the model, price source and date, actual cost and status. `scripts/agent/eval.sh` passes the flag through.
- **Docs:** I added implementation notes to sections 4 and 10 of the design doc, rewrote the AC-10.10 row and the "needs user" section in `docs/handoff/p8.md` (the Anthropic SDK wording is gone), and added an external-model section to `agent/README.md`.

## Choices I made
- **No `provider_error` status.** A separate status would keep these failures out of the 5% invalid-output rate, so I used `invalid_output`. Only 401, 402, 403 and 404 are treated as fatal and stop the whole run.
- **The adapter's own `max_tokens`.** It uses its own value (default 8192) instead of the loop's 2048, because thinking tokens count against it.
- **External hard-line misses are report-only.** They are listed in section 7 but don't change the `--check` exit code.
- **`--limit` on test or hard.** A `--limit` smoke run there still writes `runs.log`, so smoke tests should use dev.
- **`runs.log` lines.** `eval.sh --check` appended two lines to each of the test and hard `runs.log` files (baseline and stub, new code fingerprint, results unchanged). They are in this commit. I did not regenerate `docs/eval/agent-2026-11-06.md`, so its section 8 is now two lines behind.
- **Test updated.** I changed the exact-dict assertion on `tokens` in `test_evaluate.py` to include the three new keys. They are `cache_hit`, `cache_miss` and `reasoning`, all 0 for local models.
- **System prompt.** I left `system.md` unchanged because there is no dev-set evidence for a change.
