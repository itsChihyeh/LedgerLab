P8-T07c is done and committed as `fb92294` on `p8`. The Python suite is 313 tests, all green. Two `runs.log` files are left modified in the working tree and not committed, as explained below.

**What changed (AC-10.4, AC-10.9)**
- **Budget hint.** Every user message that returns tool results now ends with a line the Agent writes itself, outside `<tool_data>`. It reads `Budget: x/12 tool calls and y/8 model turns used.` With 3 or fewer tool calls left it adds "Only n tool call(s) left; on your next turn call submit_conclusion." The correction messages for an invalid conclusion or a plain-text reply carry it too.
- **Final turn.** When tool calls or model turns run out, the model gets one more request with only `submit_conclusion`.
  - A valid conclusion there gives `status=ok` and `final_turn_submit=True`.
  - No submit, another tool, plain text or an invalid conclusion gives `budget_exhausted`. There is no correction round on this turn.
  - This turn counts in `turns`, so `turns` can reach 9.
  - Extra tool calls in the same reply beyond the limit are not run; they come back as error results.
- **Report.** A new metric `final_turn_submit` appears as a row in the overall table and in the `eval` summary line. I did not regenerate `docs/eval/`.
- **System prompt.** New rule 10 gives the work order: `get_issue`, then `search_sop`, then the evidence the clause names, then submit.
- **Trace.** `eval` and `investigate` take `--trace-dir`, off by default. Each question gets a JSON file with the status, conclusion, per-turn text, stop reason, usage and reasoning length, tool calls with the extracted records, and the fabricated and malformed citations. It never contains reasoning text or keys.
- **File writes.** `agent/src` must not write files, so the trace dict is built in `trace.py` and written by the new `agent/eval/trace_files.py`. The launcher passes the writer to `cli.main`.

I added the implementation notes to sections 3 and 4 of `docs/design/investigation-agent.md`.
