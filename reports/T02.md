P8-T02 is finished and committed on `p8` as `bfbcb03`: the new bank line search by reference (AC-10.3) and a server-side test that proves the agent's routes are read-only (AC-10.2).

**What I did**
- **AC-10.3, `GET /api/bank-lines?reference=<ref>`:** it returns `{reference, lines, truncated, asOf}` in a single REPEATABLE READ snapshot on the readonly data source.
  - `lines` holds only the current (highest) version of each bank transaction. Each line has the same shape as `bankLine` in `/api/bank-lines/{id}`.
  - Lines are ordered by booking date, then bank transaction id.
  - The cap is 100 lines; beyond that it returns the first 100 with `truncated:true`.
  - `reference` must be 1–128 visible ASCII characters, otherwise 400. An unknown reference returns 200 with an empty array.
  - The existing view was enough, so there is no migration. The route does not collide with `/api/bank-lines/{bankTxnId}`.
- **AC-10.2, `AgentRouteAllowlistTest`:** it reads `agent/src/ledgerlab_agent/routes.json` and fails if the file is missing. For each route it checks:
  - the method is GET and the path starts with `/api/` but not `/api/demo`;
  - the path contains none of `resolve`, `corrections`, `cancel`, `seed`, `actions`, `query`, `accept`, `demo`, `webhook`;
  - exactly one GET handler serves it, and its class is in a hard-coded list;
  - every mapping that overlaps the path is GET-only;
  - the handler's dependency chain contains `investigationDataSource` and no other `DataSource` bean;
  - a real request on an empty database returns 200 or 404, never 5xx.
- **Files changed:** `WorkbenchQueries.java`, `WorkbenchQueryController.java`, the two new test classes `BankLineSearchTest` and `AgentRouteAllowlistTest`, and notes in `docs/design/investigation-agent.md` and `docs/design/contracts.md`.
