    - SSE timeline.
    - Twelve-invariant panel. A failure turns red, shows the violation detail and links to the named object.
    - Counter cards split into "来自账本查询" and "演示动作观察到的被拒次数".
    - Last reset time and 7-day archive.
    - Sandbox report panel, showing "尚无运行报告" when there is none.
  - **Behaviour**:
    - `#/` becomes the demo page only when `GET /api/demo/archive` returns 200 (demo profile). The old overview moves to `#/overview`, and the default profile is unchanged.
    - It sets no cookies and loads no third-party scripts. It posts `/api/demo/visit` once per load.
    - It is single-column on a phone with no horizontal scroll.
- **Sandbox report**: `frontend/sandbox-report.ts` is a Vite plugin that copies the newest `docs/runs/sandbox-*.json` into the build as `/sandbox-report.json`. It picks by the time recorded inside the file, falling back to file modification time.
- **Fault switch**: `ledgerlab.test.break-refund-lock` lives in the test source set only.
  - **Test-source classes**: `BrokenRefundLimitGuard` and `BrokenRefundApiPostProcessor`.
  - **Main-code change**: `JdbcRefunds` now takes the guard through an `ObjectProvider`; the old public constructor is kept.
  - **Why two classes**: the refund HTTP layer already takes the funds lock first, so swapping the guard alone still let one of the two refunds be rejected. The post-processor rebuilds `RefundApi` on a ledger view whose `lockFunds` does nothing.
  - **Bean test**: `RefundLockSwitchTest` shows the broken classes are absent in default and demo contexts and present only with the switch.
- **E2E backend**: `DemoE2eApplication` runs the demo-profile app with the real simulator jar, seeded as `reset.sh` seeds the site.
- **Review points**:
  - kill-worker's description says "租约过期、重新领取（代数 +1）".
  - The internal-token header value never appears in any page response or in the page's raw SSE messages.
  - The page's EventSource is wrapped by a test-only init script to capture the raw messages.
