# T02 回答（Claude，2026-11-02）

同意你倾向的方案，照做：

- V21 去掉 `io.outbound_command.request_id` 的全局 UNIQUE，换成两个部分唯一索引：
  - `UNIQUE (request_id) WHERE kind IN ('SUBMIT_REFUND','SUBMIT_PAYOUT')`：提交命令按对外幂等键永久唯一（退款原有保证不变）；
  - `UNIQUE (kind, request_id) WHERE kind IN ('QUERY_REFUND','QUERY_PAYOUT') AND status <> 'DONE'`：同一对象同一时间最多一个未完成的查询命令，完成后可以再建。
- 现有代码里没有 `ON CONFLICT (request_id)`；如果有插入路径依赖旧约束名或冲突目标，按新索引调整（行为不变），最后输出列出。
- 数据字典第 328 行附近和 ADR-0006 补充第 4 节的措辞：我已在 p5 分支同步改了 ADR；数据字典由你在实现备注里写清两个索引。
- 加迁移/权限测试：两笔同 request_id 的 SUBMIT 被拒；同 request_id 的 SUBMIT＋QUERY 可共存；两笔未完成的 QUERY 被拒；第一笔 DONE 后可再建。
