# ADR-0005 退款受理与执行分开；提现双门槛

状态：已采纳（P0）。来源：复核 S3，修订立项 Q6。

## 背景
“允许可用款为负”让账平了，但没回答谁出钱：商户提光以后再退款，平台手里没有这笔钱。Stripe 在余额不足时会让退款处于 pending。

## 决定
- 受理只看这笔支付还能退多少；受理即记 `REFUND_ACCEPTED`，商户可用可以因此变负，页面显示为“商户欠款”。
- 执行（发给处理方）要等资金覆盖：等待队列按受理顺序，放行满足 `Σ前缀 ≤ 可用 + Σ等待中` 的最长前缀。覆盖来源只算 `merchant_available`。
- 提现同时要求 `P ≤ merchant_available` 和 `P ≤ bank_cash − payout_in_transit − max(0, −processor_receivable)`。
- 银行现金永远不为负（INV-5）。

## 备选
- 余额不足直接拒绝退款：对顾客不友好，也不符合真实平台。
- 覆盖来源加上待结算款（Stripe 的做法）：执行更快，但待结算款的手续费未定，首版保守。
- 滚动保证金：多一个参数，单商户下收益小。

## 后果
退款多一个 `AWAITING_FUNDS` 状态和一个队列；“刚收款就退款”会等到批次结算才执行，页面和 API 要说清楚。
