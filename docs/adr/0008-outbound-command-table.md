# ADR-0008 出站命令用自建窄表

状态：已采纳（P0）。来源：R5 定论。

## 背景
退款提交和提现提交是我们主动调用外部的副作用。数据库提交了、调用失败或超时，或者调用成功、提交前崩溃，都要能恢复。

## 决定
- `io.outbound_command`：与业务状态同一事务插入；字段有 `request_id`（固定的对外幂等键）、`attempts`、`next_attempt_at`、租约、`external_ref`、`last_outcome`。
- worker 用 `FOR UPDATE SKIP LOCKED` 抢命令并设租约；调用外部在事务外；回执和业务状态更新在新事务里提交。
- 结果不明进 `UNKNOWN`，指数退避加抖动重试；接管过期租约者先查询再决定是否重发。
- 没有“放弃即失败”的状态。

## 备选
Spring Modulith 事件登记表（`event_publication`）：现成的至少一次投递，但不记外部引用、没有“结果未知”和查询语义，监听器失败只会重新发布。它继续只负责模块边界检查。

## 后果
多写一张表和一个 worker；换来的是每一次外部调用都有可审计的记录，故障测试可以精确地在“调用前/调用后/回执写回前”注入崩溃。

## 补充（2026-10-21，随 ADR-0016）
Stripe 的幂等键至少保留 24 小时、之后可能被清理。退款命令在结果未知时**先查询再重发**（按 `metadata.ledgerlab_refund_id` 查这笔 charge 的退款）；距第一次发送超过 20 小时，只有查询确认 Stripe 上没有这笔退款才允许重发。模拟银行的提现接口按请求号永久去重，仍然先查后发，保持同一套逻辑。
