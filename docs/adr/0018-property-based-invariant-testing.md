# ADR-0018 随机化不变量测试从 P1 开始

状态：已采纳（2026-10-21，P0）。来源：交接说明第 14 节第 2 项；立项 Q5。

## 决定
- 用 jqwik 的有状态测试：每个操作是一个 Action（请款、批次、银行入账、退款、提现、重复投递、乱序投递、在指定点崩溃、时钟前进），随机组合成序列，在 Testcontainers 的真实 PostgreSQL 上执行。
- **P1 就建起框架**，只有请款、重复、乱序和崩溃几个动作；每个阶段把新功能的动作加进去。动作清单和覆盖情况写在测试报告里。
- 每一步之后检查：INV-1～INV-11（借贷平衡、余额重算、不可为负的账户、退款不超额、资金效果唯一等），以及余额和状态与**独立的参考模型**一致。参考模型几十行纯 Java，不复用业务代码。
- **重放一致**：每条序列跑完以后，把 inbox 里的全部事件在一个空库上按原顺序重放一遍，最终余额、各对象状态和按 `source_key` 归并的分录集合必须与原库相同。
- 固定种子可复现；失败时 jqwik 收缩出最短序列，作为回归用例保存。
- CI 每次至少 1000 条序列；夜间任务跑更多（例如 10000 条），报告条数、平均长度、不变量违反次数。
- 对外表述：它覆盖的是生成器能表达、参考模型能判断的情况；不等于并发测试（并发另有栅栏和受控交错，见 AC 0.3），也不证明“没想到的情况也没问题”。

## 后果
简历数字形如“[N] randomized event sequences, 0 invariant violations”，N 来自 CI 或夜间报告的实测值。
