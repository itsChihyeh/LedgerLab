# ADR-0010 对账：精确匹配优先、零容差、可重放的运行

状态：已采纳（P0）。来源：复核 I3，修订 R4；Blnk、Hyperswitch、Modern Treasury。

## 决定
- 两段对账：账本 ↔ 处理方结算单（按 `processor_payment_ref`、`processor_refund_ref`、`batch_id`），处理方批次 ↔ 银行流水（按 `batch_id` 和 `bank_request_id`）。
- 只有精确匹配会自动配对；模糊匹配（金额相同、时间相近）只生成候选，挂在差异上供人工或 Agent 参考，**不自动销差**。
- 金额零容差。手续费单独比：实际手续费对合同费率算出的预期值，不一致报 `FEE_MISMATCH`。
- 每次运行记录输入文件哈希、规则版本、截止时点；同样输入重跑结果一致。
- 规则是数据（版本化配置），可 dry run：只出报告、不写差异。
- 老化检查逐笔检查每一项未了结义务（修订 R1）。
- 重复的定义：同一 `statement_line_id` 或同一 `bank_txn_id` 出现两次才算重复；同一支付的多次部分退款、同一批次的两笔真实入账都不是重复。

## 后果
对账结果可以用模拟器真值计算误报、漏报和“未确定”的数量，并公开报告。

## 补充
- 差异类别不强制互斥：同一批次可以同时有 `FEE_MISMATCH` 和 `BATCH_TOTAL_MISMATCH`。批次合计在按行身份去掉完全重复的行之后再比较。
- `TIMING_DIFFERENCE` 是带到期时间的未完成项，不是“正常”。
- 可配置的只有截止时间、等待窗口、老化阈值；不做通用规则 DSL，不设金额容差。
- 老化只能发现“有开始记录、没有结束记录”的义务；一笔业务在所有可见输入里都不存在时，老化查不到，这个边界要写在报告里。

## 补充（2026-10-23，T11 历史重放实现）

来源：T11 云端 Claude 三轮答复。优先用只追加历史重建证据时点状态：批次历史补原因和明细 fetch 引用，旧记录不回填；银行匹配从现有现金分录恢复，不新建历史表。需要改 P1 inbox 路径的 PARKED 老化延后 P3，先补只追加状态历史；限制写进 AGING summary 和 phases 的 P3 开工前置。

AGING 负责把 PROCESSOR/BANK 的到期时间差解释为“已升级为 …”，同时产生老化发现；入口差异沿用原识别键与处置，运行只追加 finding。ALL 在同一事务、同一读快照内顺序运行三个类别，避免半套报告。历史缺字段的 HELD 覆盖边界、阈值配置与银行期间规则已同步 contracts、data-dictionary、state-machines、money-model；对应 AC-5.7、5.9、5.11、5.12、5.20。
