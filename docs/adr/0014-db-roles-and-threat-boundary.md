# ADR-0014 数据库角色与威胁边界

状态：已采纳（P0）。来源：立项 Q3、复核 I4、R8。

## 决定
- 三个角色：`migrator`（DDL）、`app`（见数据字典第 0 节的最小权限）、`readonly`（只能读 `ledger`/`core`/`recon` 的视图）。
- 对 Agent 的调查接口用一个独立的数据源，连接 `readonly`；Agent 进程只能调用窄的、有类型的工具，没有任意 SQL。
- 测试要实测整条调用链最终用的是哪个凭证（例如在调查接口里执行写操作必须得到权限错误）。
- 威胁边界写清楚：防的是 Agent 被提示注入后写库、调查接口被滥用；不防持有 `migrator` 凭证的人。

## 后果
只读靠角色权限，不靠 `READ ONLY` 事务（Datadog 对官方 Postgres MCP 的案例）。

## 补充（对照 Codex C 路）
- 主应用所有模块共用 `app` 凭证；Modulith 校验的是代码依赖，不是数据库沙箱。这一点在 README 的威胁模型里如实写明：它不能抵御进程内任意代码。
- 调查工具的每个结果都带“截至账本序号 / 时点”；Agent 访问不到故障注入、管理接口、任意 URL、文件或 shell。
- 公开演示的只读要落实在服务端路由和部署配置上，不只是隐藏按钮。
- 2026-10-21 修订（ADR-0017）：公开部署不再是纯只读，而是“只读查询＋演示动作白名单”。白名单之外的写接口（纠错、取消退款、运营操作）在公开配置里不注册；演示动作有限流。
