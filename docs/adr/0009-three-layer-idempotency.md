# ADR-0009 三层去重

状态：已采纳（P0）。来源：复核 I5；Formance、Apache Fineract 幂等文档；Brandur。

## 决定
| 层 | 键 | 寿命 |
|---|---|---|
| API 幂等记录 | `(client_id, Idempotency-Key)`＋请求指纹 | 24 小时 |
| 业务操作编号 | `merchant_refund_ref`、`merchant_payout_ref` | 永久 |
| 分录 `source_key` | 每个业务事实一个 | 永久 |

重复请求返回**原操作的结果**，不是对象当前状态。同键并发首次提交：后到者 `409`；同键不同内容：`422`。

## 理由
幂等记录过期以后，同一个退款重放不能变成第二笔退款；同一个退款“已执行”被 webhook 和批次行各报一次，也只能记一次账。三层各防一类重复，任何一层单独都不够。

## 后果
退款和提现 API 要求客户端带业务编号；页面和模拟客户端负责生成。

## 补充（2026-10-21，开工前审查）
- 业务操作编号要返回“原操作的结果”，原结果永久存在业务对象的 `initial_result` 上；24 小时后会被清理的 API 幂等记录不能作为它的来源。
- 入站 webhook 另按 `event_id` 去重（ADR-0007）；AC-2 把它和这三层合称“四层”，两种说法指的是同一套机制。
