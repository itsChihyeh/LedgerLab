# 对账调查 Agent 评测报告（2026-11-06）

**这份报告是什么**：在冻结的评测集上，对两种本地实现按设计第 8.3 节逐项打分：规则基线（`baseline.py`，把 SOP 的判别特征写成 if/else）和替身（`stub_model.py`，把同一套规则翻译成工具调用和结构化结论，经过同一个 Agent 循环和校验器）。所有数字由 `ledgerlab-agent eval-report` 生成，没有手写。

**这份报告不是什么**：替身等于规则基线经过模型接口，**不代表任何大模型的能力**；它的分数只证明 Agent 循环、校验器和核验器没有丢信息。规则基线在封闭的原因表上本来就很强（规则是照着开发集写的），高分不说明它能处理组合故障或表外情形。大模型的价值（解释质量、规则没覆盖的情况）要等外部模型那一列。

**数据集**：开发集 66 题、测试集 67 题，由模拟器注入故障后生成并冻结（`agent/eval/data/`，设计第 8.1、8.2 节）。题型：单一原因、组合（同一提现上叠两种故障）、提示注入（银行 memo 写入指令）、证据被截留（回放时把判别所需的工具结果改成 503，应当拒答）。**回放模式的局限**：工具只能读到爬取快照里的记录，爬取范围外的请求一律 404；快照只有一个时刻；过滤组合只录了四种；`asOf` 是生成时刻而不是模拟时钟。
