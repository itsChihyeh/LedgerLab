# P2 验收清单

2026-10-23。P2 = 结算批次、模拟银行入账、两段对账与老化、对应页面，范围见 [phases.md](../design/phases.md)。开工前置决定（截止时点与证据时点分开、银行精确匹配与早到等待、发现与处置分表、联邦银行假日日历）已写进 `docs/design/`，提交 `23f5a06`。

做法：Claude Code 把 P2 拆成 18 个小任务（T01–T16，审查中插入 T09b、T13b），每个任务写明范围、AC、测试场景和不许碰的文件；Codex 在本机实现、自测、本地提交；本机再独立跑一遍 verify 全绿才推到 `p2`；Claude 在云端看 diff、再独立重跑后才继续下一个。每个提交正文带 `Task: Txx`，便于按任务查看。Codex 共停下提问 9 次，问题和回答都按任务留档（不在本仓库主线里）。

## 1. 合并方式

一个 PR：`p2` → `main`，基于当前 `main`（`0b544af`），不叠加。合并这一个就完成 P2。

## 2. 自己验收（前提：JDK 25、Node 24、Docker 在运行）

```sh
./mvnw verify                              # 主应用：1009 个测试，全部跑在真 PostgreSQL 上（本机约 27 分钟）
./mvnw -f simulator/pom.xml verify         # 模拟器：99 个测试
cd frontend && npm ci && npm run check && npm run test:e2e   # 前端单测 12 个；Playwright 两个场景共 6 个
sh scripts/smoke-p2.sh                     # 三进程冒烟：fake Stripe → relay → 主应用 → 银行流水 → 对账
```

冒烟脚本用一次性的 compose 项目名和公开的假凭证（`compose.smoke.env`），不读 `.env`，结束时删掉自己的容器和卷，不碰本地开发数据库。成功时输出：在途 0、银行现金 9680、商户可用 9680、9 条 posting、0 条差异；证据在 `target/smoke-p2/`。

可选：`./mvnw -Pmodel test -Dtest=PaymentModelProperties` 跑 1000 条随机序列（现已包含批次、分页中断、打款失败与重打、银行文件、WAITING 到期），报告在 `target/model-report.md`。

## 4. 值得看一眼的地方

1. **新增迁移** V6–V12（主应用）和 V3–V4（模拟器），每张新表都写了 `migrator`/`app`/`readonly` 授权；已提交的迁移没有改动（`scripts/check-migrations.sh` 通过）。
2. **ADR-0010** 末尾追加了一节“补充（2026-10-23）”，记录历史重放取证的取舍，而没有新开 ADR。原有内容未改。
3. `payments` 模块新增公开类 `PaymentSettlement`（供 `settlement` 锁定并结清支付）。Modulith 边界测试通过；它是模块对外接口的一部分。
4. 新增两个 HTTP 导入入口：`BankStatementController`（银行流水 CSV）和 `ProcessorSnapshotController`（处理方快照）。
5. CI 新增 `P2 three-process smoke` 任务，只能在 GitHub 上验证；本机和云端都跑过脚本本身。
6. `.gitleaks.toml` 只为 `compose.smoke.env` 里两个明显是假的凭证加了白名单（按路径和完整值双重限定）。

## 5. 夜里替你定下、可以推翻的取舍

- 开工前置 ①②③ 的写法；工作日日历用联邦银行假日，所以 AC-5.3 的银行流水日期改到 11-12。
- 乱序的 `payout.paid`、`payout.failed` 比批次先到时先挂起，批次建立时唤醒。
- 银行流水 PENDING→BOOKED 视为同一行的新版本；其他内容变化才算版本冲突。
- 非 CAD 银行流水不记账，标为 `UNMATCHED_NO_POSTING` 并开差异（不进 CAD 账户）。
- 差异再次被发现时刷新它的预期、实际金额和证据引用。
